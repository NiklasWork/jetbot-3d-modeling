## D-015 — The robot code gets its own git repo, cloned under repos/

Date: 2026-09-11
Addresses: D-011
Decision: The robot's code moves into `github.com/janniskrn/robotic-jetbot` (the human's second account), so it reaches the JetBot by `git pull` instead of by hand. The repo is cloned into the workspace at `repos/robotic-jetbot/` as a real nested git repo, git-ignored by the workspace. This replaces the "not as nested git repos" clause in D-011's consequences; everything else in D-011 stands — two independent projects, Truss carries no code.
Rationale: Copying three scripts to `~/jetbot-3d/` by hand is the step that breaks first when two machines edit them. A shared remote makes Mac and robot the same two clients of one history. Nesting is what a second git history costs; the alternative D-011 foresaw, `git subtree split`, keeps the code in this history and therefore keeps the manual copy.
Consequences: `repos/robotic-jetbot/` is in `.gitignore`, so its 169 MB never enters the Truss history; `.trussignore` already excludes `repos/`. The clone lands **beside** `repos/robot/`, not on top of it — the scripts move later, by the human's choice, and until then `repos/robot/` stays canonical. Two properties inherited from the repo being an unmodified public fork of `NVIDIA-AI-IOT/jetbot` must be settled before the robot pulls it: our code becomes public and a PR from the fork targets NVIDIA by default, and a clone on the device adds a second `jetbot` package tree beside `/home/jetbot/jetbot/` — 169 MB against 1.5 GB free, plus the namespace trap `repos/robot/README.md` documents. OD-006 carries that question.
